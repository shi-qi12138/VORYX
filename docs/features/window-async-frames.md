# Vulkan 窗口双帧提交规格

关联 F05/F09/F14，目标版本 `0.1.0-draft.20`。平台验证见环境报告。

- 设备能力公开窗口帧槽上限。Vulkan Presenter 配置两个槽，应用仍按 AcquireFrame、Submit、Present 顺序处理一个活动帧。Present 消费令牌后可以获取下一帧，即使前一帧尚在途。
- 使用 SubmitMode::Async 显式启用异步。提交令牌标记 GPU 执行完成。呈现资源由独立的呈现 fence 保护。默认同步路径和旧式清屏接口仍可用。
- AcquireFrame 在帧槽尚忙时支持立即查询与有限等待。获取图像的等待在扣除帧槽等待后使用剩余预算；成功取得图像后完成原有的获取同步。窗口实际可并行帧数还受交换链图像可用性约束。
- 复用相同窗口绘制契约并测试连续呈现、过期句柄、取消、提交前置错误、同步与异步切换，以及 Presenter 销毁和既有尺寸变化路径的安全退役。首批使用固定尺寸下的双帧循环验收，重建和析构可等待旧帧；显式限时关闭见 [限时关闭规格](window-shutdown.md)。
- 测试在 Win32、X11 与原生 Wayland 运行，并通过迁移安装后的示例执行同一流程。

相关文档见 [窗口帧 API](../window-frame-api.md) · [接口契约](../api-reference.md) · [验证矩阵](../validation.md)。
